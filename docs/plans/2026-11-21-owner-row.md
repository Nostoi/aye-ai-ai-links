# Web save works before any agent key exists (#330) Implementation Plan

> Write each test red first and confirm it fails on behaviour.

**Goal:** On a fresh install, the signed-in owner can save (and do every other owner-scoped write) before making an agent key.

## Grounding

- **Benefit (reachable today, OBSERVED in #330's reproduction):** fresh `AYE_DB` + `AYE_AUTH_DB`, `owner set`, start, sign in, `POST /save` → 500 `StoreError: Owner "owner" does not exist`. Refused at `SqliteStore.insertSync` (`src/store/sqlite-store.ts`, the `Owner … does not exist` throw); `ProfileStore` has the same refusal (`src/store/profile-store.ts`). After `keys create`, the same save answers 200.
- **Cause (OBSERVED):** the links database's `users` row is written only by `SqliteStore.ensureUser` (the one `INSERT INTO users`). Non-test callers: `KeyStore.create` only (`src/store/key-store.ts`). `owner set` (`src/cli/owner.ts`) writes only the auth database, creating the auth `user` with id `AYE_OWNER || "owner"` and name `AYE_OWNER_NAME || "Owner"`. A signed-in caller's owner is the auth user's id (`src/auth/session.ts`: `owner: response.user.id`); an OAuth app acts as the same auth user.
- **Fix (PROPOSED_NEW):** at server start, after the auth database is opened and migrated, ensure a links-database `users` row for every auth `user` (id and name), idempotently (`ensureUser` is `ON CONFLICT DO NOTHING`).
  - **Why start covers every login (OBSERVED):** the server opens the auth file with `locking_mode = EXCLUSIVE` for its whole life (`openAuthDatabase`, `src/auth/better-auth.ts`), and `owner set` refuses while it is held (`SERVER_RUNNING`, `src/cli/owner.ts`). Sign-up is closed, so a login is only ever created while the server is stopped; the next start sees it.
  - **Placement:** reading the auth `user` table belongs in `src/auth/` (a small `loginOwners(authDb)` returning `{id, name}[]`); `src/start-server.ts` calls it and `ensureUser` on the links database, once, before the server listens.
  - Rejected: writing the row in `owner set` (would also need the links database path and lock there, and leaves an install that already ran `owner set` broken until it is rerun); ensuring on each request or sign-in (a write on a read path, for an event that happens once).
- `ensureUser` never changes an existing row's display name; non-goal to sync names.
