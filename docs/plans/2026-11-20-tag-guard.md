# Keep the owner's tags from an AI's guess (#354) Implementation Plan

> Steps use checkbox (`- [ ]`) syntax. Write each test red first and confirm it fails on behaviour.

**Goal:** An AI's guessed tag list never removes, renames or relabels a tag the owner gave. The owner's ruling (2026-11-20, on #354): "keep yours", mirroring #342 — an AI's guessed list may add guesses and remove its own guesses; every tag the owner gave (stated/asked) stays; removing or changing one of the owner's tags needs the AI to say the owner asked; an owner's tag never turns into a guess.

## Grounding

- **Benefit (reachable today):** MCP `update_link` (`src/mcp/server.ts`, schema `tags: tags.optional()`) and the in-app Ask AI chat (same tools in process) reach core `updateLink` (`src/core/links.ts`), where `if (tags !== undefined) patch.tags = normalizeTags(tags);` builds a patch with no source check; `SqliteStore.updateSync` then deletes all the link's `link_tags` rows and attaches the new list (`src/store/sqlite-store.ts`, after the guarded UPDATE). OBSERVED. The #352 design challenge reproduced it: a stated `meetings` disappears when `update_link` sends inferred `[productivity]`.
- **Who asks (PROPOSED_NEW):** the tag list is a set, so "the owner asked to remove X" can't be read from one tag's source. `update_link` gains an optional `tagsSource: "stated" | "asked" | "inferred"`: who decided this tag set. Absent or `"inferred"` → a guess, guarded. `"stated"`/`"asked"` → the owner's own set, replaced as today. This mirrors the why's `{text, source}`. Each tag's own `source` keeps its meaning (who gave that tag).
  - Rejected: reading the owner's say from "any tag in the list is stated/asked" (an AI copying the owner's existing tags with their sources would silently gain the right to drop one); refusing all AI changes to owner tags (the owner ruled that an AI acting on their request may).
- **The guarded rule (core decides, store applies atomically):** for a guessed set G and the link's current tags C at write time:
  - every tag in C whose source is stated/asked stays, with its name, source and kind;
  - a key in both G and an owner tag of C keeps the owner's source (never downgraded to inferred);
  - inferred tags of C not in G are removed; new keys in G are added as given;
  - order: tags that remain keep their current relative order; new keys follow, in G's order. So a guess never moves the owner's space (`linkSpace`: first pinned tag in order, `src/core/link-space.ts`).
  - The merge must happen inside the store's write transaction against the tags read there (as `whyOver`/`intentOver` decide atomically), not from a read in core: core sends `patch.tags` plus `patch.tagsGuess: true`; `SqliteStore` and `FakeStore` apply the rule in `update`. One pure helper in core (`src/core/tags.ts`, e.g. `mergeGuess(current, guess)`) computes the result, and both stores call it on the tags they read in the transaction, so the rule lives once.
- `save_link` is unchanged: a new link has no owner tags yet; a repeat save discards tags (OBSERVED, guidance line "the tags you sent are discarded").
- Owner paths are untouched: Edit link (`applyEdit`), Save (`addTags`, #352) and tag rename/merge/delete do not go through `updateLink`'s tag patch.
- Guidance (`src/mcp/guidance.ts` `UPDATE_LINK`, 2048-character cap, tested in `src/mcp/guidance.test.ts`): say that a guessed tag set keeps the owner's tags; to remove or change one at the owner's request, send `tagsSource: "stated"` (or `"asked"`).

## Non-goals

No change to tag rename/merge/delete tools, to `save_link`, or to the web dialogs. No guard on `kind` beyond what a kept tag already keeps.

- [ ] Red tests (pure): keeps every stated/asked tag absent from the guess; never downgrades an owner tag present in the guess; removes inferred tags absent from the guess; adds new keys after the kept ones; keeps current order of kept tags.
- [ ] Red tests (contract, via `updateLink`): owner `meetings` (stated) + guess `[productivity]` → `[meetings, productivity]`, `meetings` still stated; `tagsSource: "stated"` with `[productivity]` → `[productivity]`; guess `[]` keeps owner tags and drops guesses; a pinned owner space stays the link's space after a guess adds another pinned tag; an owner tag added between core's call and the store's write (simulate by a direct store write before `update`) is kept — the merge reads inside the write.
- [ ] Red tests (validation): `tagsSource` that is not a source is `invalid_input`; `tagsSource` without `tags` is `invalid_input`.
