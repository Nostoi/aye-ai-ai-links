# Tidy up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner let go of old links without losing them. This plan adds a **Put it away** state that comes back when a newer focus entry fits it, renames **I'm done with it** to **It's stale**, and adds a five-link **Tidy up** session.

**Architecture:**
- Put-away is *archived plus a date*. `links.state` stays `active | archived`, and a new nullable `put_away_at` column marks an archived link as put away rather than stale. Existing `state === "active"` filters keep a put-away link out of lists, digests and Worth a look.
- The marker's meaning is owned by one core rule: every write that sets `state` decides `putAwayAt`. Only `putAwayLink` sets it, and every other state write clears it. This covers the web, MCP `update_link` and the in-app AI alike.
- Coming back follows the owner's ruling of 2026-10-21, "show it while it fits". It is evaluated read-only whenever Worth a look or the digest is built. A put-away link shows on Home and in the digest, with a `came_back` reason, while a focus entry newer than its `putAwayAt` and inside the focus window keyword-matches it. It rejoins the lists only when the owner opens it or chooses Bring it back.
- Undo follows the repository's existing contract (ROADMAP 2026-10-19, delete with Undo): it applies only while the link is still exactly as the action left it, by state and put-away marker. A personal, single-owner app accepts that an identical later decision can be undone by an older Undo, as today. The three cross-model challenges kept escalating the concurrency promise; this plan states the real one instead.
- The Tidy up queue and session rules live in `core/`; the web page only shows them.

**Tech Stack:** TypeScript, Hono, SQLite (better-sqlite3), vitest, linkedom, biome. Node 22.

**Spec:** `docs/specs/2026-10-21-tidy-up-design.md` (visual reference `docs/design/tidy-up-mockup.html`). Issue #198. Revised after three cross-model challenges (REVISE at 4fc2eb0, 097275b and v3; their objections were accepted or ruled on in this text) and the owner's ruling "Show it while it fits".

## Spec deviations (decided at planning, recorded on #198)

1. **What "back" means.** The spec's Claude call, "back in its lists" as soon as it matches, is replaced by the owner's ruling of 2026-10-21, "Show it while it fits". Opening it or Bring it back returns it to the lists.
2. **Handy tiles.** A tile's ⋯ menu keeps its two rows. Put it away is offered on the link's card everywhere else.
3. **No "Five more".** The finish screen offers Back home only. Home's start line returns whenever five more links qualify, which avoids a button whose promise goes stale during the session.
4. **Gone pages.** They are left out of Tidy up and of coming back. Home's gone row stays the one place that asks about them.

## Review Focus

1. **A link put away *after* a matching focus entry exists must not come back from that entry.** Only entries created later count. Tested in Task 2.3.
2. **Undo applies only to the state its action left.** Put away (tab A), then stale (B), then A's Undo is a conflict, because the marker differs. Undo of Put it away restores the snooze it cleared. Tested in Task 2.2.
3. **Stale through MCP must clear the marker.** `update_link {state: "archived"}` on a put-away link leaves `putAwayAt` null, so the link never comes back. Tested in Task 2.2.
4. **A Tidy up session whose queue shrinks under it.** Another tab, or an AI, acts on one of the five.
   - A choice whose precondition no longer holds, such as Keep or Put it away on a link that is now archived, gets a 409. The page then shows the reload message without advancing.
   - A choice that still makes sense, such as It's stale on a link put away elsewhere, applies.
   - Tested in Task 3.3.
5. **An inferred focus and no current focus.**
   - With an inferred focus, the fit line and Home's came-back reason say "(a guess)".
   - With no current focus, there is no fit line and no empty box, and Put it away is still offered.
   - Tested in Tasks 2.4 and 3.2.

## Part 2 (PR 2): Put it away

One mechanism carries Part 2: the marker `putAwayAt`. An archived link with it set is put away; without it, the link is stale. Only `putAwayLink` sets it. Every other write that sets `state`, from any door, clears it. An Undo restores what its action replaced, but only while the link still carries exactly the state and marker that the action left.

```ts
/** What a state action replaced and what it left; Undo sends both back. Dates travel as ISO strings. */
export type StateChange = {
  before: { state: LinkState; putAwayAt: Date | null; snoozedUntil: Date | null };
  after: { state: LinkState; putAwayAt: Date | null };
};
/** Put it away: active -> archived with putAwayAt = now; clears the snooze. */
export async function putAwayLink(deps: WorthDeps, owner: OwnerId, id: string): Promise<StateChange>;
/** It's stale: active or put away -> archived, putAwayAt null. */
export async function archiveLink(deps: WorthDeps, owner: OwnerId, id: string): Promise<StateChange>;
/** Bring it back: any archived link -> active, putAwayAt null. */
export async function bringBackLink(deps: WorthDeps, owner: OwnerId, id: string): Promise<StateChange>;
/** Undo of any of the three: only while the link matches change.after; restores change.before. */
export async function undoStateChange(deps: WorthDeps, owner: OwnerId, id: string, change: StateChange): Promise<void>;
```


The marker rule, in `links.ts`:
- Any `updateLink` patch that sets `state` also sets `putAwayAt: null`.
- `putAway: true` calls `putAwayLink`. Combining it with `state` or `handy` is `invalid_input`, refused before anything is written. The in-app AI's receipt-recording path goes through the same function, and a test proves it.
- Recording an opening (`opened: true`, or `recordOpening`) of a put-away link makes it active with `putAwayAt` null, through the same patch, so the stamp moves. A stale link stays stale.
- `snoozeLink` accepts a put-away link as well as an active one.

- [ ] **Step 1:** Write the tests:

  - **Late Undo:** put away (A) → stale (B) → A's Undo is a conflict, and the link stays stale (Review Focus 2).
  - Snoozed → put away → Undo restores the snooze.
  - Undo of stale on a put-away link restores it put away, with the same date.
  - `update_link {state: "archived"}` on a put-away link clears `putAwayAt` (Review Focus 3).
  - `update_link {putAway: true}` puts an active link away; combined with `state`, it is refused.
  - An opening of a put-away link makes it active; an opening of a stale link leaves it stale.

```ts
export type TidyLink = { link: Link; gone: boolean; fit: FocusEntry | null };
/** Up to `limit` old links, oldest saved first, then lowest id. Gone links are left out: Home's gone row asks about them. */
export async function tidyQueue(deps: TidyDeps, owner: OwnerId, limit: number): Promise<TidyLink[]>;
/** Keep: sets tidyKeptAt = now while the link is active. */
export async function keepInTidy(deps: TidyDeps, owner: OwnerId, id: string): Promise<void>;
/** Whether Home offers Tidy up: at least TIDY_SESSION links qualify. */
export async function tidyReady(deps: TidyDeps, owner: OwnerId): Promise<boolean>;
```

`TidyDeps = { store, tools, checks, profile, keywordSearch, now }`, the same parts `DigestDeps` uses. A link qualifies when all of these hold:

- `tidyKeptAt` is null or at least 180 days ago.

`fit` is the newest focus entry in the window whose keyword search returns the link. It is null when there are no current entries or nothing matches.
