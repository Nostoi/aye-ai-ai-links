Notes

  • Busy has no hook today. cardBusy is a WeakSet in tell-why.ts; whileBusy adds the card to it and removes it in finally. It sets no attribute, class or variable on the page, so there is nothing for CSS to match. The only aria-busy write in the app is the Show older link in show-older.ts.
  • Where the busy style would attach. Inside whileBusy: set aria-busy="true" on the card after a 300ms timer (cancelled if the answer comes first) and remove it in finally; CSS then matches [aria-busy=true]. That is enough for A, which only needs the card. B and C also need the pressed button, and whileBusy(card, run) is not given one, so the call sites (about ten) would pass it in. Reading document.activeElement instead is probably unreliable, since Safari is known not to focus a button when it is tapped (not checked here).
  • Other buttons on a busy card do nothing. A second press sends nothing while the first is out (whileBusy returns early). Only A shows that. With B or C the other buttons look live but are silent; they could take aria-disabled styling if you want that shown.
  • Motion. The app's prefers-reduced-motion block ends in *{animation:none!important;transition:none!important}. A spinner under it would sit still as a half-drawn ring, which reads as stuck. So C needs its own fallback: hide the spinner and show B's word. The "motion off" card above, and the Motion switch in the toolbar, show this. The pressed looks in A, B and C use transitions, so under reduced motion they simply jump, which is fine. I made the press itself instant (transition:none while active) so it feels immediate; only the release eases.
  • 300ms. The delay applies to the busy look only, never to the pressed look, which answers the finger at once. A spinner that flashes for 100ms is worse than no spinner.
  • Pressed on a phone. iOS Safari has been reported to apply :active only when the page has a touchstart listener, for example <body ontouchstart=""> or document.body.addEventListener("touchstart",()=>{}). What I could and could not confirm is in the report that came with this page. The app has no touchstart listener today, so before building any pressed option, test it on a real iPhone; if it does not show, one empty passive listener on document fixes it.
  • What each option does to each control. A works on all seven. B barely shows on the slide button and the menu row (nothing to shrink against) and is the most visible on the large Tidy choice. C's inset shadow is weak on the dark-filled .primary in light theme, because a dark shadow on dark ink barely shows; the 1px drop carries it there.
  • Pressed colours are written as mixes of --ink, as the app's hover tints are, so they follow the theme. They would join themeCss as plain :active rules, with no new tokens needed.
