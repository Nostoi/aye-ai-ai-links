# Tidy up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner let go of old links without losing them. This plan adds a **Put it away** state that comes back when a newer focus entry fits, renames **I'm done with it** to **It's stale**, and adds a five-link **Tidy up** session.

**Architecture:**
- Put-away is *archived plus a date*: `links.state` stays `active | archived`, and a new nullable `put_away_at` column marks an archived link as put away rather than stale. This leaves the `CHECK` constraint, the MCP and export enums and every `state === "active"` filter unchanged. A put-away link drops out of every list, digest and Worth a look for free.
- Coming back happens when a focus entry is written, in core `addProfile`, never on a page view. That keeps the README promise that looking at Home marks nothing.
- The Tidy up queue and session rules live in `core/`; the web page only shows them.

**Tech Stack:** TypeScript, Hono, SQLite (better-sqlite3), vitest, linkedom, biome. Node 22.

**Spec:** `docs/specs/2026-10-21-tidy-up-design.md` (visual reference `docs/design/tidy-up-mockup.html`). Issue #198.

## Global Constraints

- The copy is fixed by the spec. Use these strings exactly:
  - Choices and their lines: **Keep** "Stays in your lists, as it is now."; **Put it away** "Out of your lists. Comes back when you start something it fits."; **It's stale** "Out of sight for good. Search still finds it."
  - The marker on Put it away: "If you're not sure".
  - The Put it away bar: **Put away.** "Out of your lists but still saved. If you start something it fits, it'll come back."
  - The It's stale bar: **Let go.** "You won't see it again unless you search for it."
- Old = `savedAt <= now − 30 days` and (`lastOpenedAt` null or `<= now − 30 days`). Reuse `NOT_OPENED_MS` from `src/core/digest.ts`; don't copy the number.
- Keep wait = 180 days. Session size = 5. The Home start line shows only when at least 5 links qualify.
- "Working on now" = focus entries with `createdAt >= now − FOCUS_WINDOW_MS`. Matching is `keywordSearch` (`focus_words`), at most `FOCUS_MATCHES_PER_ENTRY` hits per entry.
- No amber anywhere in this work. Controls are at least 44px. Pages make no outside requests. Colours come only from `theme.ts` tokens.
- The wire value for stale stays `"archived"`: no change to `STATES`, the MCP enums or the export format.
- Every new signed-in POST joins `CHECKED_PAGES` (`src/app.ts`) and gets a two-owner test plus an entry in `src/mcp/isolation.test.ts`.
- Every new card action runs inside `whileBusy` (#208).
- Write each test red first and watch it fail for the intended reason. Regenerate snapshots with `npx vitest -u`, then read the diff.
- Never put the server hostname in any file.

## Spec deviations (decided at planning, recorded on #198)

1. **When a link comes back.** The spec says the match "is checked whenever Worth a look or the digest is built". This plan checks it when a focus entry is written instead. The README promises that looking at Home marks nothing, and a check-on-view would write on a GET. The owner-visible behaviour is the same: a link comes back once a newer focus entry fits it.
2. **Search fading.** The spec says "only stale links fade" in search. Search results don't fade anything today, and this plan leaves search unchanged. Put-away links therefore already "rank normally, never faded".
3. **Export.** Export keeps format v1. A put-away link exports as `archived` without its date, so re-importing it makes it stale. Recorded as a known limit on #198; a follow-up issue will be filed.

## Review Focus

1. **A link put away *after* a matching focus entry exists must not come back from that entry.** Only entries created later count. Tested in Task 2.3.
2. **Undo after the link has already come back.** The owner puts a link away, a focus entry brings it back, then a stale Undo arrives. The Undo must not archive an active link. Tested in Task 2.2.
3. **It's stale on a link that came back must clear its put-away dates.** Otherwise it would read as put away. Tested in Task 2.2.
4. **A Tidy up session whose queue shrinks under it.** Another tab, or an AI, puts away or archives one of the five. The page must refuse cleanly (409 shows the reload message) and not double-act. Tested in Task 3.3.
5. **Profile with no current focus.** No fit line, no empty box, and Put it away is still offered. Tested in Task 3.2.

**Interfaces:**

```ts
export const TIDY_SESSION = 5;
export const TIDY_KEEP_WAIT_MS = 180 * DAY_MS;
export type TidyLink = { link: Link; gone: boolean; fit: FocusEntry | null };
/** Up to `limit` old links: gone first (earliest flagged), then oldest saved, then lowest id. */
export async function tidyQueue(deps: TidyDeps, owner: OwnerId, limit: number): Promise<TidyLink[]>;
/** Keep: sets tidyKeptAt = now while the link is active. */
export async function keepInTidy(deps: TidyDeps, owner: OwnerId, id: string): Promise<void>;
/** Whether Home offers Tidy up: at least TIDY_SESSION links qualify. */
export async function tidyReady(deps: TidyDeps, owner: OwnerId): Promise<boolean>;
```

`TidyDeps = { store, tools, checks, profile, keywordSearch, now }`, the same parts `DigestDeps` uses. A link qualifies when all of these hold:
- it is active;
- it is old by Global Constraints;
- it is not a kept tool;
- `tidyKeptAt` is null or at least 180 days ago.

`fit` is the newest focus entry in the window whose keyword search returns the link. It is null when there are no current entries or nothing matches.

  - the order (gone first);
  - `limit`;
  - `fit` set and null;

  - `tidyReady` is false at 4 qualifying links and true at 5.
