# Stats Implementation Plan (#161)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Stats section on the profile page, a history log that makes its windows honest, a read-only `get_stats` MCP tool, and a weekly AI reading of what the stats say about the owner.

**Architecture:**
- **The log.** Core names each event and the store writes it in the same transaction as the state change. Undo removes the event its action wrote.
- **The counts.** The store returns per-link facts, and `core/stats.ts` holds every counting rule. Doors only render or serialise them.
- **The reading.** A timed pass in the shape of the summary pass writes the reading through the one AI connection. It starts only when `AYE_AI_` settings exist.

**Tech stack:** TypeScript, Node 22, better-sqlite3, Hono, the MCP SDK, Vitest, Biome.

**Spec:** `docs/specs/2026-10-22-stats-design.md`. Read it with this plan; it governs where they differ.

## Global constraints

- **Three PRs**, in order:
  - PR 1 is Tasks 1–3, the log.
  - PR 2 is Tasks 4–7, the counts.
  - PR 3 is Tasks 8–11, the reading.

  Run `/personal-pr-readiness` before each PR's implementation. The owner waived the ~400-line ceiling (memory: PR size waiver).
- **One branch per PR**, cut from `main`. `npm run check` must pass before every push.
- **Doors hold no rules.** `src/web/` and `src/mcp/` only translate. Counting, windows and the "before tracking began" note live in `src/core/stats.ts`.
- **Owner scoping lives in `store/`.** Every new store method takes `owner`, except the reading pass's candidates method. That one is cross-owner by design, like `summaryCandidates`.
- **Hidden links.** Every read of `link_events` joins `links` on `deleted_at IS NULL`. The table registers in `src/store/hidden-link-coverage.test.ts`.
- **Event kinds, verbatim:** `opened`, `put_away`, `stale`, `not_now`, `not_handy`.
- **Windows, verbatim:** `30`, `90`, `365`, `all`. The default is `all`. An unknown value falls back to `all`.
- **Tag rows:** the top 8 by saved count, then "and N more".
- **Reading timing:** a 1 h poll. A reading is due when none exists, or when it is at least 7 days old and the input hash changed.
- **Tests first.** Watch each new test fail for the intended reason before writing the code.
- **Page rules** (`src/web/AGENTS.md`):
  - render through `page()` and theme tokens, with no outside requests;
  - controls at least 44px tall;
  - no amber, and no space colors in the stats section.
- **Each migration is appended** to `MIGRATIONS` in `src/store/migrations.ts` and calls no app code. Confirm the next number with `MIGRATIONS.length` when you build: it was 20 on 2026-10-22.
- **README in the same PR** as the change it describes. `src/readme.test.ts` catches a missing tool.

## Review focus

These are not covered by any one task's happy path, so each owning task adds the test named here.

1. **Undo right after the action, then the action again.** Put it away → Undo → Put it away leaves exactly one `put_away` row (Task 3).
2. **An Undo refused because the link changed meanwhile** removes no event (Task 2, store contract).
3. **A deleted link restored within the Undo window** keeps its events and counts again. While hidden, it counts nowhere (Task 4).
4. **An empty library or a new owner:** the section shows zeros with no tag list and no reading, and `get_stats` returns zeros (Tasks 5 and 6).
5. **A bad AI reply** (empty, cut off, over the cap, or a thrown error) leaves the old reading in place and backs off (Task 10).

**Interfaces:**
- Consumes: `StatsReadingStore`, `getStats`, `recentFocus` (`src/core/profile.ts`), and `StatsReader`.
- Produces:
  ```ts
  export const READING_POLL_MS = 3_600_000;
  export const READING_EVERY_MS = 7 * 86_400_000;
  export function createStatsReadingPass(o: {
    readings: StatsReadingStore; stats: StatsStore; profile: ProfileStore;
    reader: StatsReader; writtenBy: string; now: () => Date;
    log?: (m: string, e?: unknown) => void; pollMs?: number;
  }): { start(): void; quiesce(): void; stop(): Promise<void>; sweep(): Promise<void> };
  ```

- Per candidate owner:
  1. Compute the all-time and 30-day stats and the focus texts.
  2. Hash them: sha256 of a stable JSON, leaving out `trackingSince` and `window`.
  3. If a reading exists and its hash is equal, write nothing.
  4. Otherwise call the reader and `putReadingIf(owner, previous?.writtenAt ?? null, …)`.

  On failure, back off in memory per owner (60 s doubling to 24 h, as the summary pass does). `stop()` aborts the call in flight and writes nothing. `writtenBy` is `config.ai.name`, or the model when no name is set; check how `AYE_AI_NAME` is surfaced in `config.ts`.
